## 4. PeeDee loyalty: approved specification vs code

The programme parameters were approved in the _PeeDee Build Specification_. The code stores the approved values as defaults, but several rules behave differently:

| Parameter                        | Approved                                                                            | Code today                                                                                  | Action                                                                                                                                  |
| -------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Exchange rate                    | 1 PD = ₦1                                                                           | Same                                                                                        | —                                                                                                                                       |
| Earn rate and timing             | 1 PD per ₦200 paid (0.5%), vested at check-in, never at payment                     | 0.5% awarded **at payment**. A second, dormant check-in formula would add 5% × tier on top. | **Decide one earning path before fixing the check-in event** — fixing the event alone would pay both — 11 to 16 times the approved rate |
| Expiry                           | 12 months from the last check-in, payment or redemption                             | 12 months from the last credit; spending does not reset the clock                           | Count redemptions (and check-ins) as activity                                                                                           |
| Redemption cap                   | 50% of booking value                                                                | 50%, but redemption is off unless `ENABLE_COIN_REDEMPTION=true`                             | Decide and set the flag                                                                                                                 |
| Tiers                            | Bronze 0–249, Silver 250–999, Gold 1,000+ lifetime PD                               | Same thresholds; multipliers only affect the dormant check-in formula                       | Follows from the earning decision                                                                                                       |
| Referral                         | Referee 200 PD; referrer 5% of referee spend for 90 days, 50 PD floor, 1,000 PD cap | Same values configured; nothing is paid because rewards hang off check-in                   | Fix with the check-in event                                                                                                             |
| Signup, birthday, streak bonuses | 20, 50 and 30 PD                                                                    | Signup works; birthday has no trigger; streak depends on check-in                           | Add a birthday job; fix check-in                                                                                                        |
| Manual adjustment ceilings       | 5,000 PD per adjustment, 20,000 PD per staff member per day                         | Same                                                                                        | —                                                                                                                                       |
| Campaign budget approval         | Budgets above ₦50,000 approved by an operations admin                               | Approved by a finance officer or super admin                                                | Confirm which is intended                                                                                                               |
| AI layer                         | Churn scoring, segment builder, copy generation                                     | Rule-based RFM scoring; template copy                                                       | Not built — design after the rules engine has outcome data                                                                              |

Ordered by impact. Flow-level defects are listed in full in [03 §8](03-App-Flow.md#8-known-flow-gaps).

| 1   | Check-in emits `visit.checked_in`; the loyalty and email handlers listen for `access.checked_in`                                                                                                                                                                                                                                                                                                    | No check-in coins, referral payouts, streak bonus or welcome email. Decide the earning model first (§4). |
| 2   | Refund clawback looks for `BOOKING_EARN` by booking; payment rewards are `TRANSACTION_REWARD` by transaction                                                                                                                                                                                                                                                                                        | Coins earned on refunded bookings are never reversed                                                     |

| 4   | Campaigns: emails sent twice when the worker runs; `channel` not saved; scheduled and event triggers never run; RFM overwrites `users.acquisitionSource`                                                                                                                                                                                                                                            | Duplicate emails, misleading UI, lost acquisition data                                                   |
| 5   | Admin actions that do nothing or fail: Settings form, walk-in pass, booking override (404), release hold and courtesy discount (unreachable); UI offers actions the API refuses                                                                                                                                                                                                                     | Staff cannot do their jobs and lose trust in the tool                                                    |
| 6   | Member app: unpaid holds hidden, simulated support tickets, checkout login redirect, Google fallback flow                                                                                                                                                                                                                                                                                           | Lost bookings and unanswered members                                                                     |
| 7   | Holds can be extended without limit; staff override skips capacity                                                                                                                                                                                                                                                                                                                                  | Slots can be squatted; spaces can be overbooked                                                          |

## 6. Recommended next steps

1. **Finish production setup** ([§3](#3-operational-readiness)): real Paystack keys and webhook URL, Google client IDs, Google verification resubmission, corrected policy text.
2. **Decide the PeeDee earning model**, then fix the check-in event wiring, refund clawback and redemption flag, and add the birthday job (debt 1–2, §4). Add a test that check-in reaches the loyalty handler.
3. **Fix the revenue-affecting flows:** show unpaid holds on My Bookings, fix the booking override route, record discount redemptions, cap hold extensions (debt 3, 5–7).
4. **Make support real:** wire the website contact form and the member app's ticket form to a real inbox or ticket system, or remove them.
5. **Turn on automatic deploys safely and schedule off-site backups** (debt 10).
6. **Work through the hardening list** (debt 8).
7. **Fix campaigns** (debt 4), then design the AI layer on top of real outcome data.
